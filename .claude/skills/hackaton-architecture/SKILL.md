# hackaton — architecture and where code goes

## Shape

One hostname per environment. `/api/*` and `/actuator/*` → backend, everything else → frontend
(nginx). The frontend calls `/api/...` on its own origin: no CORS, no hardcoded hosts.

```
backend/src/main/java/one/absent/hackaton/
  HackatonApplication.java
  config/                  cross-cutting config: OpenApiConfig, ApiExceptionHandler
  web/                     cross-cutting endpoints (InfoController)
  <feature>/               one package per feature, everything for it side by side:
    <Thing>.java             JPA entity (Lombok)
    <Thing>Repository.java   Spring Data interface
    <Thing>Service.java      logic + @Transactional, only when there is logic
    <Thing>Controller.java   @Tag + @RestController under /api/<things>, records as DTOs
backend/src/main/resources/db/migration/V<n>__<what>.sql

frontend/
  openapi.json             the API contract, written by the backend's OpenApiSpecTest (committed)
  src/app/api/             generated client (pnpm run api) — never edit by hand
  src/app/errors.ts        error interceptor + ErrorBanner
  src/app/pages/<page>.ts  one routed standalone component per page (lazy in app.routes.ts)
  src/app/components/      shared presentational components, once a second page needs one
```

Package by feature, not by layer: several people build different features at the same time, and
feature packages keep their merges apart.

## Recipe: a feature end to end

1. **Migration** `V<next>__<what>.sql` (look up the highest number first, also on `origin/main`).
   Portable SQL: `bigint generated by default as identity`, `varchar`, `timestamp with time zone`,
   no Postgres-only functions — tests run on H2 in PostgreSQL mode. Update `docs/DATA-MODEL.md`.
2. **Entity** in `<feature>/` with `@Entity @Getter @Setter @NoArgsConstructor`. No `@Data`, no
   `@EqualsAndHashCode`, no `@ToString` over relations. Hibernate only validates
   (`ddl-auto: validate`): every column needs the migration *and* the field, or the app won't start.
3. **Repository** `interface <Thing>Repository extends JpaRepository<Thing, Long>`.
4. **Controller** `@Tag(name = "<Things>")` (becomes `<Things>Service` in the frontend) +
   `@RestController` under `/api/<things>`, constructor injection via `@RequiredArgsConstructor`.
   Request and response bodies are **records**, never entities. Validate input with `@Valid` and
   Jakarta annotations on the request record. Method names become the client's method names, so
   name them like an API (`list`, `get`, `create`, `update`, `delete`).
5. **Errors**: expected cases throw `new ResponseStatusException(HttpStatus.NOT_FOUND, "Team 7 not found")`
   (or `BAD_REQUEST`, `CONFLICT`, …). The reason is shown to the user, so write it for them.
   `ApiExceptionHandler` turns it, validation errors and anything unexpected into Problem Details.
6. **Test** in `backend/src/test/java/...` with MockMvc like `ApiTest` (`@SpringBootTest`,
   `@ActiveProfiles("test")`). `./mvnw verify` needs no Docker and rewrites `frontend/openapi.json`.
7. **Client**: `cd frontend && pnpm run api` regenerates `src/app/api/`. Commit both with the change.
8. **Page** in `pages/<page>.ts`, registered lazily in `app.routes.ts`. Inject the generated
   service; reads with `toSignal(service.list())` or `rxResource`, writes with `subscribe`. State
   in signals (`signal`, `computed`), new control flow (`@if`, `@for`), standalone components only.
   Failed calls show up in the error banner by themselves; a form that shows field errors itself
   passes `new HttpContext().set(HANDLES_ERRORS, true)` and reads `err.error.errors`.
9. Check both sides (commands in `AGENTS.md`) and open a PR (workflow in `README.md`).

## Config and secrets

- Every setting lives in `application.yml` with a local default and is overridable by env var
  (relaxed binding: `app.foo-bar` → `APP_FOOBAR`).
- Secrets: `${MY_KEY}` in `application.yml`, value as repo secret `STAGING_MY_KEY` / `PROD_MY_KEY`
  (see README, "Secrets and settings"). Never a real value in the repo, also not in tests.
- Frontend runtime config comes from `/config.json` (written at container start), not from
  Angular environment files: one image runs in every environment.

## Authentication

Better Auth runs in the Node service `auth/`, routed at `/api/auth/*`, with its own Postgres
`auth` schema. The JWT plugin uses RS256 and the `hackaton-api` audience; Spring verifies
tokens against its JWKS. Accounts, password hashing and cookie sessions belong to Better Auth,
never to backend Flyway/JPA. See `docs/AUTH.md` for the environment and migration commands.
