# Plan: Business clearance in one project

USP for the pitch: a company clears an office in one project. AI turns a pasted inventory into
reviewable line items, the company compares three routes by net outcome, and publishes in one
click. Read `AGENTS.md`, `docs/LEAN-CODE.md`, `.claude/skills/hackaton-architecture/SKILL.md` first.

## 1. Goal and demo moment (45 s)

1. Logged in, click **Business** → "New clearance project": `Muster Treuhand AG`, `8004`, `Zürich`,
   deadline today + 30 days → **Create** (lands on `/business/{id}`).
2. Click **Use sample inventory** (fills the textarea), then **Read inventory**. Sample text (constant
   `SAMPLE_INVENTORY` in `business-project.ts`):
   ```
   Qty;Item;Notes
   12;Dell P2419H 24" monitors;good condition, with stands
   20;Giroflex 64 office chairs;fabric, some worn armrests
   3;HP LaserJet Pro M404dn printers;working, toner low
   8;Lenovo ThinkPad T14 laptops (2021);wiped, chargers included
   ca. 6;height-adjustable desks;electric, count tomorrow
   ```
3. Five rows appear, each with a yellow **Provisional** badge; the desks note says "Quantity
   approximate". Fix desks to 6, click **Confirm all quantities** → badges turn green.
4. Route cards show roughly (depends on demo listings): estimated resale ≈ CHF 11–12k;
   Self-service ≈ 8.1k, **Managed ≈ 8.4k (Recommended)**, Direct purchase ≈ 5.2k "fixed, paid in 5 days".
   Presenter: "Managed is how we earn — 15 % fee; Direct purchase is our resale margin."
5. Choose **Self-service** → tick all → **Publish 5 items** → status column says **Listed** with links;
   open Discover: the listings show seller "Muster Treuhand AG".

## 2. Business model and assumptions (all marked "assumption" in UI footnote)

| Route | Customer gets | We earn |
|---|---|---|
| Self-service | free; they list, answer buyers, hand over | nothing (supply for the free marketplace) |
| Managed selling | we sell; 15 % service fee on proceeds, agreed upfront | 15 % of proceeds |
| Direct purchase | fixed offer 45 % of estimated resale, paid in 5 working days | resale margin (≈ 85 % sell-through − 45 % − handling) |

Constants (one place, `ClearanceService`): `SELF_SELL_THROUGH = 0.70`, `MANAGED_SELL_THROUGH = 0.85`,
`MANAGED_FEE = 0.15`, `DIRECT_OFFER = 0.45`, `URGENT_DAYS = 14`. Comment each: `// assumption: ...`.

## 3. Data model — `V9__clearance.sql` (only file you add)

```sql
create table clearance_project (
    id bigint generated by default as identity primary key,
    owner_id varchar(255) not null,          -- Better Auth subject, no FK across schemas
    company_name varchar(120) not null,
    postcode varchar(4) not null,
    locality varchar(120) not null,
    deadline date not null,
    route varchar(20),                       -- null until chosen: SELF_SERVICE | MANAGED | DIRECT_PURCHASE
    created_at timestamp with time zone not null
);
create index clearance_project_owner_idx on clearance_project(owner_id);
create table clearance_item (
    id bigint generated by default as identity primary key,
    project_id bigint not null references clearance_project(id),
    name varchar(120) not null,
    category varchar(80) not null,
    quantity integer not null,
    quantity_confirmed boolean default false not null,
    condition varchar(20) not null,
    notes varchar(1000),
    estimated_unit_chf numeric(12,2) not null,
    listing_id bigint references listing(id)  -- set when published
);
create index clearance_item_project_idx on clearance_item(project_id);
```
Item status is derived, not stored: `listing_id` null → `DRAFT`; listing `SOLD` → `SOLD`; else `LISTED`.
Entities `ClearanceProject`, `ClearanceItem` (`@Entity @Getter @Setter @NoArgsConstructor`; item has a
plain `Long projectId` column, no JPA relation; `LocalDate deadline`; enums `@Enumerated(STRING)`,
`Condition` from `listing`). Repos: `ClearanceProjectRepository` (`findByOwnerIdOrderByCreatedAtDesc`),
`ClearanceItemRepository` (`findByProjectIdOrderById`). Add V9 row + table bullets in `docs/DATA-MODEL.md`.

## 4. API — `ClearanceController`, `@Tag(name = "Clearance")`, base `/api/clearance/projects`

All endpoints need a JWT (`@AuthenticationPrincipal Jwt user`). Load project by id; if missing **or**
`ownerId != user.getSubject()` → 404 "Clearance project not found." Item not in project → 404
"Item not found." Every mutating endpoint returns the fresh `ProjectDetail`.
**Method names must be unique app-wide** (springdoc suffixes duplicates like `list_1`):

| Method | Path | Java name | Body → result |
|---|---|---|---|
| GET | `` | `listProjects` | → `List<ProjectSummary>` |
| POST | `` | `createProject` | `CreateProjectRequest` → 201 `ProjectDetail` |
| GET | `/{id}` | `getProject` | → `ProjectDetail` |
| POST | `/{id}/items/extract` (multipart) | `extractItems` | parts `text` (String, optional), `photos` (0–5 files, optional) → `ProjectDetail` |
| PUT | `/{id}/items/{itemId}` | `updateItem` | `UpdateItemRequest` → `ProjectDetail` |
| DELETE | `/{id}/items/{itemId}` | `deleteItem` | → `ProjectDetail` |
| POST | `/{id}/items/confirm` | `confirmQuantities` | → `ProjectDetail` (all items confirmed) |
| PUT | `/{id}/route` | `chooseRoute` | `ChooseRouteRequest` → `ProjectDetail` |
| POST | `/{id}/publish` | `publishItems` | `PublishRequest` → `ProjectDetail` |

Records (all in `clearance/`, nullable fields with `@Schema(nullable = true)`):
- `CreateProjectRequest(@NotBlank @Size(max=120) String companyName, @NotNull @Pattern("[0-9]{4}") String postcode, @NotBlank @Size(max=120) String locality, @NotNull @FutureOrPresent LocalDate deadline)`
- `UpdateItemRequest(@NotBlank @Size(max=120) String name, @NotBlank @Size(max=80) String category, @Min(1) @Max(10000) int quantity, boolean quantityConfirmed, @NotNull Condition condition, @Size(max=1000) String notes)`
- `ChooseRouteRequest(@NotNull Route route)`; `enum Route { SELF_SERVICE, MANAGED, DIRECT_PURCHASE }`
- `PublishRequest(@NotEmpty @Size(max=100) List<@NotNull Long> itemIds)`
- `ProjectSummary(long id, String companyName, String locality, LocalDate deadline, Route route /*nullable*/, int itemLines)`
- `ProjectDetail(long id, String companyName, String postcode, String locality, LocalDate deadline, long daysLeft, Route route /*nullable*/, List<ItemView> items, Totals totals, List<RouteOption> routes, Route recommendedRoute, String recommendationReason)`
- `ItemView(long id, String name, String category, int quantity, boolean quantityConfirmed, Condition condition, String notes /*nullable*/, BigDecimal estimatedUnitChf, BigDecimal estimatedTotalChf, ItemStatus status, Long listingId /*nullable*/)`; `enum ItemStatus { DRAFT, LISTED, SOLD }`
- `Totals(int itemLines, int units, BigDecimal estimatedResaleChf, int draft, int listed, int sold)`
- `RouteOption(Route route, BigDecimal netChf, BigDecimal serviceFeeChf, boolean certain, String timeframe, String yourWork)`

Rules: `extractItems` → 400 "Paste an inventory list or add photos." when text blank and no photos;
text > 10 000 chars → 400; photos: same type/size checks and messages as `DraftController` (copy the
constants, do not import them). `updateItem`/`deleteItem` on a listed item → 409 "This item is already
listed." `updateItem` recomputes `estimatedUnitChf`. `publishItems`: route must be `SELF_SERVICE` (409
"Choose Self-service to publish listings yourself."), each item unlisted (409 "… is already listed.")
and confirmed (409 "Please confirm the quantity of {name} first."). Per item create a `Listing`:
title = name; description = `"{notes} Quantity: {q} pieces, price per piece. From the office clearance
of {company}."` (notes omitted when null, cut to 4000); category, condition, priceChf =
estimatedUnitChf; postcode/locality from project; createdAt now; sellerId = subject; **sellerName =
companyName**; attributes empty; no image. `listings.save(...)` then `item.setListingId(listing.getId())`.
Whole method `@Transactional`.

`SecurityConfig`: add `.requestMatchers("/api/clearance/**").authenticated()` before `anyRequest()`.

## 5. AI step (`ClearanceService.extract`)

`ai.ask(SYSTEM, text-or-"Inventory from photos.", images, SCHEMA, AiInventory.class)` — default model
`claude-sonnet-5-5` (`ai.model`). `record AiInventory(List<AiItem> items)`,
`record AiItem(String name, String category, int quantity, Condition condition, String notes)`.
SYSTEM rules (static String, like `DraftController.SYSTEM`):
- One item per distinct product/model line; never merge different models; never split one line.
- name: concise, brand and model first when given, max 80 chars; never invent brand or model.
- quantity: the stated integer; "ca.", "~", "about", "?" or counted from photos → best integer and
  notes start with "Quantity approximate, please count."; 1 if none given.
- condition: from the text/photos; if not stated use USED and add "Condition not stated." to notes.
- category: best fit from the enum; printers, scanners, projectors, desk phone systems → Office equipment.
- notes: max 200 chars, factual (accessories, wear, data wiping as stated); no claims of function.
- Ignore header rows, totals and lines that are not items; at most 50 items.
SCHEMA: object `{items: array of {name: string, category: enum[Computers, Laptops, Monitors, Phones,
Tablets, Office furniture, Office equipment, Audio, Cameras, Household, Other], quantity: integer,
condition: enum[NEW, LIKE_NEW, GOOD, USED, DEFECTIVE], notes: string}}`, all fields required,
`"additionalProperties": false` on every object. Server: clamp quantity to 1..10000, cut name to 120,
`quantityConfirmed=false` for every new item, notes blank → null. Images are only sent to the AI,
not stored. Tests mock `AiClient` with `@MockitoBean` (no network).

## 6. Route maths (`ClearanceService`, static, unit-tested)

- Instance method `estimateUnit(category, name, condition)` calls `priceEstimator.estimate(category, name).midChf()`
  and passes it to static `unitPrice(BigDecimal mid, String category, Condition condition)`:
  if null use `FALLBACK_CHF` (Computers 300, Laptops 300, Monitors 90, Phones 200, Tablets 200,
  Office furniture 150, Office equipment 80, Audio 80, Cameras 300, Household 40, other/unknown 50);
  multiply by condition factor (NEW, LIKE_NEW, GOOD 1.0; USED 0.8; DEFECTIVE 0.2); round to whole CHF
  (HALF_UP), minimum 1. Stored on the item at extract/update time.
- `G` = Σ quantity × estimatedUnitChf over all items (incl. listed/sold).
- Self-service: net = G × 0.70, fee 0, certain=false, timeframe "6–8 weeks", yourWork "You list,
  answer buyers and hand over {lines} item lines".
- Managed: proceeds = G × 0.85, fee = proceeds × 0.15, net = proceeds − fee (= 0.7225 G),
  certain=false, timeframe "3–4 weeks", yourWork "Give us site access once".
- Direct purchase: net = G × 0.45, fee 0, certain=true, timeframe "Paid within 5 working days",
  yourWork "Nothing — we collect everything".
- All amounts rounded to whole CHF. `daysLeft = deadline − today(Europe/Zurich)`.
  Recommend: `daysLeft < 14` → DIRECT_PURCHASE, reason "Only route that clears the site before the
  deadline."; else highest net (MANAGED), reason "Highest expected net outcome without your team's time."
  Empty project → G = 0, still three options.

## 11. Acceptance criteria

- Demo script §1 works end to end in under 45 s with a real API key.
- Without login every `/api/clearance/**` call is 401; another user's project is 404.
- New items are provisional; publish refuses unconfirmed items and non-self-service projects.
- Route cards show three nets that follow §6 exactly and a recommendation with reason; fees are labelled as assumptions.
- Published items are normal `AVAILABLE` listings on Discover with the company as seller; project shows
  them as LISTED with links, totals update.
- `./mvnw verify` and all frontend checks green; `openapi.json` + client committed.

## 12. Out of scope

Real managed/direct-purchase operations, contracts, payouts and reports; storing photos or attaching
them to listings; spreadsheets as files (.xlsx/.csv upload — paste text instead); video; lots/bundles;
multi-user roles and approvals; site access details; marking items sold (SOLD only via listing status);
editing or unpublishing listed items.

## 13. Risks

- **Migration order:** V9 merged before another team's V8 breaks Flyway on staging (V8 then "older
  than applied"). Merge V8 first or renumber at merge time.
- AI latency/outage: 503/502 lands in the error banner; demo with a working key, keep sample short.
- Estimates depend on demo listings and on `PriceEstimator`, which another team may change — demo
  numbers are approximate; tests assert maths in `ClearanceRoutesTest` only.
- Multipart `text` part: if the generated client mistypes it, switch to `@RequestParam("text")` and
  regenerate. Shortcut: one listing per line with quantity in the description, not per unit.
